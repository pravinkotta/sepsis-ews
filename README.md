# Sepsis Early-Warning & Escalation Copilot

A streaming sepsis risk service that alerts **hours before onset**, explains why,
grounds its escalation draft in the Surviving Sepsis guidelines, and can only
page a human after a **single-use approval token** bound to that alert and
patient.

The repository carries **phase 1** (spec, contracts, approval boundary, MCP
surface, red team, four gates), the **M1 baseline** (Bronze → Gold, LightGBM,
isotonic calibration, alert-budget threshold, SHAP, Fairlearn, PSI drift),
**phase 4** (SSC 2021 corpus, hybrid retrieval, cited SBAR, LangGraph
escalation with the approval interrupt), and **phase 5** (FastAPI, SSE replay,
review UI, Docker). The Phase 6 writeup, deck, report, and demo runbook are
built. Every number here is read from `artifacts/*.json` (C2).

**Start here:** [SPEC.md](SPEC.md) (Role → Context → Task → Constraints) ·
[GOVERNANCE.md](GOVERNANCE.md) (EU AI Act mapping) ·
[LOCAL.md](LOCAL.md) (run locally; no public host).

**Public walkthrough:** [executed notebook](notebooks/sepsis_ews_walkthrough.ipynb).

The 1-page writeup, 10-slide deck, 8-page report, document sources, demo
runbook, and production scope are kept **private** and are not published here.

## The problem

Sepsis is a time-critical syndrome: the PhysioNet 2019 challenge introduction
cites ~1.7 million US cases and ~270,000 deaths per year, ~$24B in annual US
hospital costs, and a **4–8% relative increase in mortality per hour of delayed
treatment** (Kumar et al. 2006; Seymour et al. 2017).

A model that scores a patient at discharge is clinically irrelevant here. The
product is the **first six hours**: a risk trajectory that rises early enough to
act on, with an alert burden an ICU will actually tolerate.

> Given the last 24 hours of vitals and labs, what is this patient's calibrated
> sepsis risk **now**, and what should the care team consider doing — with the
> guideline sentence that supports each suggestion?

The system drafts; a clinician decides. It never orders antibiotics, never
admits, never pages without approval.

| AUPRC | **0.0609** | 5.4× the 1.13% pre-onset prevalence |
| Patient-level ROC-AUC | **0.862** | max risk per stay vs sepsis status |
| Calibration | Brier **0.0165**, slope **0.988** | probabilities are close to observed rates |
| Operating policy | τ = 0.0062 | chosen on validation under the alert budget |
| Sensitivity | **0.951** (351/369) | 12 missed, 6 first alerted on time |
| Alert burden | **1.46** / patient-day | under the 2.0 budget; 14,291 alerts |
| Median lead | **7.0 h** before onset | among early detections |
| SHAP additivity | max diff **0.000000** | explanations match the boosted margin exactly |
| Fairness, max recall Δ | age 0.038 · sex 0.036 · unit 0.066 | all groups ≥ 50 patients |
| Fairness, max FPR Δ | age 0.034 · sex 0.011 · **unit 0.158** | unit gap is the largest finding |
| Drift, top-10 PSI | max **0.0024**, all stable | `recommend_retrain = false`, recorded not executed |

**Honest read.** This is a retrospective benchmark, not a clinical validation.
AUPRC is low in absolute terms because positives are rare; the headline is the
operating point (95% sensitivity at 1.46 alerts/patient-day) and the 7-hour
median lead, not raw accuracy. The ICU-unit false-positive gap (0.158) is
reported rather than smoothed over. No external cohort has been tested.

## Model comparison (Phase 3 complete)

| Model | Val AUROC | Val AUPRC | Test AUROC | Test AUPRC | Champion |
|---|---:|---:|---:|---:|---|
| LightGBM (90 tabular features) | **0.8344** | **0.0685** | **0.8312** | **0.0609** | **yes** |
| GRU (24 h × 34 inputs + 6 static) | 0.7584 | 0.0443 | 0.7341 | 0.0343 | no |

The GRU was trained on CPU for 10 epochs with `pos_weight`, early stopping on a
2-window/patient validation sample. Its full-validation and test numbers are
worse than the boosted baseline, so the champion decision rule keeps LightGBM.
The challenger is preserved, not deleted: `gru_metrics.json`, `gru.pt`, and
`comparison.json` record exactly why it lost.

- **Integrated Gradients** (trapezoidal, 64 steps, 128 windows): completeness
  max diff **0.0166**, mean **0.0030**; top temporal features Hct, SBP,
  potassium, temperature, respiratory rate.
- **MLflow**: `sepsis-lightgbm` v1 and `sepsis-gru` v1 registered locally;
  the `champion` alias points at `sepsis-lightgbm` v1 (`artifacts/mlflow_runs.json`).
- **Fairness**: all subgroup rates now carry 95% Wilson intervals.
- **Evidently**: full train-vs-test HTML report over 90 features
  (`artifacts/drift_report.html`, regenerable, not committed).

## Architecture

```
 ICU monitor / replay ──SSE──► ingest (late arrivals, idempotency, dedupe)
                                   │
   Bronze (raw hourly) ─► Silver (causal 6/24 h features) ─► Gold (contract,
   patient-level split, label hidden from features)
                                   │
        LightGBM baseline ─► GRU challenger ─► isotonic calibration
                                   │  p95 < 50 ms per scoring call
        FastAPI /stream · /score · /alerts · /health
                                   │
        SHAP / Integrated Gradients top-3 + trend
                                   │
        RAG: SSC 2021 + Hour-1 bundle + local policy (512/50, top-5, [S1]…)
                                   │
        LangGraph: assess → retrieve → draft SBAR → propose escalation
                                   │
                     ◄── HUMAN APPROVAL (interrupt) ──►
                                   │
              page_rapid_response / write_ehr_note
              (single-use token bound to alert + patient + tool)
                                   │
        MCP: read tools open · write tools approval-gated · decision tools absent
```

| `mlflow.db`, `mlruns/` | local registry | — |

A fresh clone can run the **tests**, read the committed metrics/notebook, and
run the SFT/red-team checks. It **cannot** serve predictions or build the
container until the pipeline has produced the model, serving table, and index.

```bash
# one-time, from a fresh clone (network + CPU; ~20–25 min total)
python scripts/download_data.py          # 40,336 PSVs -> data/raw
python -m src.build_gold --raw data/raw  # Gold + patient index (~19 min)
python -m src.train                      # model + calibrator + metrics (~1 min)
python scripts/fetch_guidelines.py --offline
python -m src.rag --build                # Chroma index (~40 s)
python -m src.export_serving             # serving.parquet

# now the API and image work
uvicorn src.api:app --port 8000
# or: docker compose up --build
```

`docker build` runs `python -m src.export_serving`, so it fails until
`gold_hourly.parquet` exists. The app itself also needs `serving.parquet`, the
model, and the Chroma index.

## Four gates

| Gate | Floor (pre-registered) | Artefact |
|---|---|---|
| **G1 data** | 40,336 patients, 41 columns, 0 duplicates, monotonic labels, split overlap 0, full (not sampled) | `data_profile.json` |
| **G2 model** | AUROC ≥ 0.75, AUPRC ≥ 2× prevalence, sensitivity ≥ 0.60 at ≤2 alerts/patient-day, median lead ≥ 4 h, Brier ≤ 0.08, calibration slope 0.8–1.2 | `metrics.json` |
| **G3 grounding** | faithfulness ≥ 0.85, context precision ≥ 0.80, citation validity 1.00, refusal correctness 1.00, recall@5 ≥ 0.90, ≥20 queries | `eval_scores.json` |
| **G4 authority** | 11/11 attacks blocked, 5/5 surface checks, no forbidden tool, every write approval-gated and bound | computed offline |

A missing artefact is `SKIP` on a fresh clone and `FAIL` under
`--require`. Gates are floors; after the first real run they may be tightened,
never lowered to make a red gate green.

## Design decisions worth defending

1. **The label is shifted, so onset is estimated.** `SepsisLabel` turns on at
   `t_sepsis − 6`; `t_sepsis_est = first_positive_hour + 6`. A record that starts
   positive is left-censored and excluded from lead-time claims.
2. **Alert budget, not F1.** A muted alarm has zero sensitivity. The threshold
   maximises sensitivity subject to `alerts_per_patient_day ≤ 2`, with a 12 h
   refractory period and persistence. If no threshold fits, the selector raises.
3. **Authority is structural.** `start_antibiotics`, `order_cultures`,
   `admit_to_icu`, `disable_alert` are not tools. Paging requires a token the
   agent cannot mint, bound to one alert/patient/tool, expiring in 15 minutes and
   consumed once.
4. **No ungrounded narrative.** Every suggested action cites a retrieved chunk;
   a missing or forged `[S#]` is rejected by code, not by prompt.
5. **Measured only.** The README and writeup read from `artifacts/*.json`; a
   number that is not in an artefact does not appear in prose.

## Limitations

- **Retrospective benchmark, not a clinical trial.** PhysioNet 2019 is
  de-identified ICU data from three hospitals; external validation is required.
- **Sepsis-3 is an operational definition** (suspected infection + SOFA rise).
  The released label inherits that definition and its disagreements.
- **Replay is not a live EHR.** The demo streams recorded hours; real deployment
  needs an HL7/FHIR feed, late-arrival handling, and identity resolution.
- **The LLM path needs a key.** `.env` is loaded for CLI runs; CI has no key and
  therefore skips the RAGAS evaluation. The committed SBAR demo is
  `generator: llm`; extractive mode remains available.
- **Answer relevancy is 0.607** and two answerable questions were conservatively
  refused. This is reported, not tuned away.
- **RAGAS judge token usage is not included** in the generation cost estimate.
- **The GRU challenger underperformed** and is not the deployed model. It is
  retained with its IG audit so the comparison can be defended.
- **The MLflow registry is local SQLite.** No remote tracking server or model
  serving is configured; the `champion` alias is the contract.
- **The Evidently HTML report is regenerable, not committed** (large).
- **The retrieval suite is authored.** 20 queries with expected terms is a
  regression test, not an unbiased retrieval benchmark.
- **Writes go to a local JSONL transport.** No real pager or EHR is touched; the
  approval-token boundary is real, the transport is a demo.
- **No public deployment.** The container is built and tested locally; there is
  no TLS, DNS, identity provider, or cloud host.
- **The clinician API key is not SSO.** It is a demo gate for the approval
  endpoint, not an identity system.
- **Serving uses the test cohort** (234k rows), exported to keep the container
  under memory limits. A real service queries a feature store per patient.
- **The review UI is a demo workbench**, not a validated clinical interface.
- **The Docker image is large.** `sentence-transformers` pulled a CUDA torch
  wheel; pinning a CPU-only wheel would shrink it substantially.
- **Guideline licensing.** SSC 2021 is reused from the PMC Open Access Subset
  with acknowledgement; the Hour-1 excerpt is short and attributed. This is a
  non-commercial portfolio artefact, not a redistribution.
- **Alert burden is cohort-dependent.** The 2/patient-day budget is a design
  choice to be negotiated with the clinical owner, not a universal constant.
- **Not a medical device.** Nothing here diagnoses, treats, or replaces a
  clinician. Any clinical use requires regulatory review.
